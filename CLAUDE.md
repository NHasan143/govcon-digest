# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Govcon Digest — a news/magazine website built on the "NewsBoard" Next.js template. Next.js 16 App Router (Turbopack for both `next dev` and `next build`; stay on 16.x — Payload 3.92 supports `next >=16.3.3 <17`), React 19, TypeScript, Bootstrap 5 (CSS only), Payload CMS 3. The package is ESM (`"type": "module"` — which is why the PostCSS config is `postcss.config.cjs`).

This codebase was adapted from an earlier publication ("Morning Glance"). It is intended as a reusable base: site identity, database, and deployment are all left configurable rather than baked in.

**Site identity is environment-driven.** `lib/config.ts` exports a single `SITE` object (name, initials, tagline, description, base URL, Twitter handle, postal address, contact emails) read from `NEXT_PUBLIC_*` variables — see `.env.example`; `.env` is gitignored. All metadata, JSON-LD, sitemap/robots/manifest/RSS routes, headers, footer, and contact components consume `SITE` — never hard-code the site name, domain, address, or emails; add new values to `lib/config.ts` and both env files. `metadataBase` in `app/layout.tsx` comes from `SITE.url`, so page-level `openGraph.url` values are relative paths. `NEXT_PUBLIC_*` values are inlined at build time — a rebuild is required after changing them. Remaining template branding to clean up as content is defined: some thematic copy in the About page and section components, and `alt="newsboard"` attributes on demo images.

## Commands

```bash
npm run dev                  # Dev server at http://localhost:3000
npm run build                # Production build
npm run start                # Serve the production build
npm run lint                 # ESLint CLI, flat config in eslint.config.mjs (Next 16 removed `next lint`)
npm run analyze              # Next's built-in Turbopack bundle analyzer (`next analyze`)
npm run migrate              # Apply Payload DB migrations
npm run payload -- <cmd>     # Payload CLI (e.g. migrate:create after schema changes)
npm run generate:types       # Regenerate payload-types.ts after collection changes
npm run generate:importmap   # Regenerate the admin import map (after adding admin components)
npm run mfa -- <email>       # Enroll a CMS user in TOTP 2FA (--disable to remove)
                             # (runs via `node --env-file=.env --import tsx` — `payload run` silently no-ops in this setup)
```

There is no test runner. Auth and access checks are standalone scripts — `scripts/test-cms-auth.ts`, `scripts/test-user-management.ts`, `scripts/test-public-access.ts`, `scripts/test-upload-types.ts`, `scripts/test-rate-limit.ts` (how to run them: `docs/cms-access.md`).

After changing any Payload collection: run `npm run payload -- migrate:create <name>`, commit the generated file in `migrations/`, and run `npm run migrate` in every environment. Also rerun `generate:types`.

## Architecture

**Route groups — three root layouts.** `app/` has no root layout; instead: `(frontend)` holds the public site (its `layout.tsx` is the html/body shell with the site Layout, fonts, theme), `(payload)` holds the Payload admin panel and its REST/GraphQL API, and `(cms-login)` holds the standalone CMS login page. Metadata routes (`sitemap.ts`, `robots.ts`, `manifest.ts`, `feed.xml/`), the newsletter API route (`app/api/newsletter`), server actions (`app/actions/`), and `favicon.ico` stay at `app/` root. `app/(frontend)/[...notFound]/` catch-alls unmatched URLs into the styled 404.

**Site architecture (URLs and indexing rules).** **Two-level category system**, defined once in `lib/categories.ts`: seven top-level sections (government-contracting, defense, artificial-intelligence, cybersecurity, federal-technology, financial-news, executive-moves), each with three subsections — twenty-eight slugs in all. **Slugs are flat and globally unique**: a subsection lives at `/{subSlug}/` exactly like a section, so the one `/{category}/` hub route serves both levels. The parent/child link is navigation and aggregation only — `getCategoryFamily(slug)` returns a section plus its three children (or a lone subsection), and that feeds both the section hubs and the homepage section rails. The module exports `CATEGORY_TREE` (nav/footer/topics), `CATEGORIES` (flat, for routing/sitemap/validation), `PARENT_CATEGORIES`, `CATEGORY_OPTIONS` (CMS select, children indented) and `getSection()`. Each section carries a `color` used for hub rules, kickers and generated cover art. CMS pages: `/latest`, category hubs `/{category}` with crawlable self-canonical pagination at `/{category}/page/N` (N≥2; page 1 is the hub root), **every article — Post or News — at the root, `/{slug}`** (category is filing and displayed metadata, never part of the URL; `articleUrl()` in `lib/cms.ts` builds every article link). Categories and articles share the root namespace: `app/(frontend)/[category]/page.tsx` renders a hub when the segment is a category slug and otherwise looks the slug up as an article (`getArticleBySlug()`, Posts then News; body/metadata in `components/cms/Article.tsx`). The shared slug field `payload/fields/articleSlug.ts` rejects on save any slug already used in either collection, any category slug, and any top-level route name in its `RESERVED_SLUGS` list — **add to that list when creating a new top-level page**, or a same-named post would save but be unreachable (static routes win). Legacy `/{category}/{slug}` and `/stories/{slug}` URLs 308-redirect to `/{slug}`. News is a separate `news` Payload collection (`payload/collections/News.ts` — same fields and category options as Posts but no homepage-hero flags; the collection itself is the "news flag") with its index at `/stories` (force-dynamic, like `/latest`), `/topics` (the seven sections with their subsections listed under each — the landing page for the footer Topics links), `/author/{slug}` (all articles across posts+news; `/authors` is the author index, and the template demo `/author` redirects there), `/topic/{slug}` (matches tags across posts+news) (**noindex,follow** until a topic is approved for indexing), `/subscribe` (the newsletter landing; `/newsletter` redirects there; archive is Phase 2 — not built), and legal pages `/editorial-standards`, `/privacy`, `/terms`, `/cookie-policy` (boilerplate copy — review before launch). `/search` is **noindex,follow** and queries Payload live (`searchPosts()` in `lib/cms.ts` — `like` match on title/excerpt/tags across both posts and news, published only; the header search icon opens `SearchForm`, a GET form to `/search?q=`; `?query=` accepted as alias). Shared listing UI in `components/cms/` (`PostList`, `CategoryHub`). The nav (desktop `MainMenu.tsx`, mobile `MobileMenu.tsx`) is center-aligned and built from `PARENT_CATEGORIES`: Latest followed by the seven section names, each opening its three subsections on hover (template CSS `li:hover > ul.sub-menu`; the section label itself links to its hub). Seven full section names only fit one row because `.govcon-nav` in `app/(frontend)/globals.css` sizes the items with `clamp()`, and because the search icon and the black "Subscribe" button now sit in the **masthead** (`components/layout/header/Header.tsx`) rather than at the right of the navbar — they collided with "Executive Moves" there. The template's icon swap is scoped to `header .search-icon`, so globals.css repeats those rules for `.masthead .search-icon`. No Home/About/Contact/Newsletter links (the masthead logo links home; About/Contact live in the footer's Company column). Comment UI was removed site-wide (no comment forms, counts, or Most/Recent-comments widgets), and the header's MORE offcanvas ("Don't Miss") is gone.

**Homepage (CMS-driven).** `(frontend)/page.tsx` is `force-dynamic` and is built from purpose-written blocks in `components/home/`, not the template's demo sections (since deleted) — those carried hard-coded fallback articles, and the rule that the homepage only ever renders real CMS posts is easier to keep when the components have no defaults at all. Block order: **hero** (`HomeHero.tsx` — two stacked stories left, the lead story centred, a five-item LATEST rail right), **Today's Highlights** (five across), **Editor's Picked** (one lead beside a numbered list of four), then **one rail per section** in registry order, each pulling from `getSectionPosts(getCategoryFamily(slug), …)` so it shows that desk's coverage rather than whatever is newest site-wide. Every section rail is the same `CardRow` (four across); it prefers posts not yet on the page and tops up with the section's own already-shown posts, so a rail is only short when the section itself has fewer than four. The hero's three featured slots stay editor-controlled — `sliderFeatured` supplies the lead, `featured` the two beside it (**hard max 4**, and a post can't have both flags — enforced by a `beforeChange` hook in `payload/collections/Posts.ts`) — and any slot an editor leaves unticked is filled from the newest posts so the band is never ragged. The page tracks a `used` set as it allocates, so no post appears twice; a block with nothing to show is skipped and a fully empty pool renders a "No articles yet" state.

**Homepage alignment.** `components/home/home.module.css` is where the grid discipline lives, and the reasons matter if you edit it. (1) Every grid track is `minmax(0, …)`, never a bare `1fr` — the line-clamp helpers use `display: -webkit-box`, whose min-content width is the *unwrapped* text, so an `auto` minimum makes columns refuse to shrink and the page overflows on narrow screens. (2) Every image sits in a fixed `aspect-ratio` box with `object-fit: cover`, so nothing below it can shift. (3) Kickers, headlines and excerpts carry both a line clamp and a matching `min-height`, so cards in a row share baselines even when one category pairing wraps to two lines and its neighbour does not. Dropping a `min-height` is what breaks a row, not the copy. The footer (`components/layout/footer/Footer.tsx`) is static: logo (48px) + `SITE.tagline` + an address column (from `SITE.address`), a Category column (the seven sections), a Company column (Home/News/Topics/About/Contact/Editorial Standards), and the legal pages (Editorial Standards/Privacy/Terms/Cookie) in the bottom bar below the divider. The contact form uses Google reCAPTCHA v2 when `NEXT_PUBLIC_RECAPTCHA_SITE_KEY`/`RECAPTCHA_SECRET_KEY` are set (`components/elements/Recaptcha.tsx`, verified in `app/actions/contact.ts`; silently disabled when unset). Posts also carry an editable `lastUpdatedAt` date ("Last updated" on the article page and in JSON-LD; falls back to the doc's automatic `updatedAt`). `lib/cms.ts` also exports `mediaUrl()`, which strips the serverURL origin Payload prefixes onto media URLs — always use it when rendering media (absolute URLs break `next/image` and go stale after domain changes). `scripts/seed-govcon.ts` (run: `node --env-file=.env --import tsx scripts/seed-govcon.ts`, `--reset` to wipe and redo) seeds 75 published posts spread across all twenty-eight categories plus 7 editor authors — enough to fill every homepage block and give each hub more than one page. **All of it is placeholder copy: companies, figures and events are invented to demonstrate layout, and it must be replaced before launch.** Cover art is *generated*, not photographic — `scripts/lib/cover-art.ts` draws six families of abstract editorial figures as SVG and rasterises them with sharp at a fixed 3:2. That is deliberate: stock photos arrive at arbitrary aspect ratios, which is exactly what breaks a card grid. Hue comes from the section, lightness is stepped per subsection, and the pattern family is assigned round-robin by position (hashing it from the slug left whole rails drawing the same figure). `--reset` deletes the seeded covers too, so a palette change actually takes effect. The previous `scripts/seed-content.ts` was removed — its category values no longer exist.

**Template demos — removed.** The template's demo pages (`/home-2`, `/home-3`, `/single*`, `/category*`, `/typography`, `/basic-search`, `/login`, `/signup`), their section components, the mock API (`app/api/articles|authors|categories`, `lib/data.ts`) and the simulate-only auth/article/search actions were deleted; those URLs now 404. Their names stay in `RESERVED_SLUGS` so no article can claim a generic URL like `/login`. If an old URL ever needs to go somewhere, add it in the CMS Redirects collection rather than restoring a page. `Layout` renders only the one site `Header` (the demo `Header2`/`MainMenu2`/`OffcanvasSidebar` are gone). Some unused template components remain in `components/` (e.g. `sections/about|author|contact/Section1`) — check before reusing; they may carry demo copy.

**CMS (Payload 3).** Config in `payload.config.ts` (root); collections in `payload/collections/` (Posts with drafts + SEO group (metaTitle/metaDescription/ogImage + `customSchema`, a validated JSON-LD textarea shared with News via `payload/fields/customSchema.ts` and rendered additively by `components/CustomSchema.tsx` on both article pages — invalid JSON is rejected on save and skipped at render) + slug auto-format via `payload/utils/formatSlug.ts` + single-featured `afterChange` enforcement + an admin-only `hidden` checkbox that removes a post from the entire public site without unpublishing — public read access is `published AND hidden != true`, and field-level access lets only `role: admin` toggle it. The Posts list view has admin-only bulk "Hide on site"/"Show on site" buttons (`payload/components/BulkVisibilityActions.tsx`, wired via `admin.components.beforeListTable`) acting on checkbox-selected rows through the REST bulk PATCH, and a Hidden column custom cell (`payload/components/HiddenCell.tsx`) whose `.post-hidden-marker` class drives the tinted-row styling in `app/(payload)/custom.css` — after adding admin components run `npm run generate:importmap`; Media with thumbnail/card/hero sizes into `/media` on disk, accepting only raster images (`image/jpeg|png|webp|avif|gif` — no SVG, which can carry scripts, and no video; Payload checks the file content, so renamed SVG/HTML/text files are rejected too; `next.config.mjs` has no `dangerouslyAllowSVG`, so the optimizer refuses SVG; verified by `scripts/test-upload-types.ts`); Users with administrator-only create/update/delete, public read limited to author fields (anonymous responses carry only id/name/slug/socials — `stripPrivateUserFields` in `payload/access/userPrivacy.ts`; when adding a user field the public needs, add it to `PUBLIC_USER_FIELDS`), Admin/Editor/Suspended roles (suspension revokes sessions and blocks login; final active admin protected) + MFA group + a `socials` group (linkedin/facebook/twitter/instagram/website URLs, rendered by `components/elements/AuthorSocials.tsx` on /authors and /author/{slug})). The admin panel lives at the **workspace path `/newsroom`** (never mention it in robots.txt; the folder `app/(payload)/newsroom/` must be renamed if `routes.admin` changes). CMS articles render at `/{slug}` (published only; Lexical content via `@payloadcms/richtext-lexical/react`; the editor has `EXPERIMENTAL_TableFeature` enabled so doc tables paste as real tables — styled in `app/(frontend)/globals.css` under "Article tables"). Posts carry a required `category` select (options from `lib/categories.ts`); Users carry a `slug` for author pages. The sitemap (`app/sitemap.ts`) is `force-dynamic` — published posts and active authors appear automatically, no rebuild needed.

**Public query allowlist (SQL-injection hardening).** Anonymous visitors may only filter, sort, count or list distinct values on the fields the website itself queries: `payload/access/publicQueries.ts` defines one allowlist per public collection (Posts, News, Users, Media), applied as a `beforeOperation` hook. Anything else — rich-text/JSON contents, SEO fields, `_status`/`hidden`, private account fields, `author.*` traversal — gets a generic 403 and one `Refused anonymous query` warning line in the server log (with IP). Signed-in users and server code with `overrideAccess` are not restricted. Reason: Payload's public REST/GraphQL accept arbitrary field paths, which is where its SQL-injection bugs lived (GHSA-v49j-62m6-pgrr, GHSA-pj7x-6wpf-pgvp; fixed in 3.88/3.90). **When the site starts filtering or sorting on a new field, add it to that collection's list**, or the query will 403. App code never builds SQL — all queries go through Payload's API with user input only as values; keep it that way. Verified by `scripts/test-public-access.ts` (run against a copy of the DB). Payload packages are pinned to an exact version and must move together. Security `overrides` in package.json force patched versions of transitive packages — revisit each on every Payload upgrade and drop it once Payload's own dependency is patched: `sharp` (one patched copy shared with Next.js's image optimizer), `dompurify` (pinned by `monaco-editor` in the Payload admin), `happy-dom` (major bump under `@lexical/headless`; only its `/dom` entry loads happy-dom and Payload never imports that entry, so the override clears the advisory without touching a runtime path), and `esbuild` under `@esbuild-kit/core-utils` (an unused loader in `drizzle-kit`). Known and accepted: `deepmerge` (low, no fixed release exists; Payload only feeds it config and signed-in users' save data). Check with `npm audit --omit=dev` after every dependency change; if an override ever reappears as `invalid` in `npm ls`, delete its stale nested entries from package-lock.json and reinstall. Payload 3.92 requires Node `^22.23.4 || >=24.22.1` (`engines`).

**Security headers.** `next.config.mjs` sends `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN` + `Content-Security-Policy: frame-ancestors 'self'`, `Referrer-Policy: strict-origin-when-cross-origin` and `Permissions-Policy: camera=(), microphone=(), geolocation=()` on every response (pages, API, CMS, uploads, static files), and `poweredByHeader: false` removes `X-Powered-By` (including the one Payload's `withPayload` adds). `Strict-Transport-Security: max-age=31536000` is sent only when `NEXT_PUBLIC_SITE_URL` is `https://…` at build time — never ship it before HTTPS works; `includeSubDomains` is off until every `govcondigest.com` subdomain is confirmed HTTPS. The CSP is deliberately frame-ancestors-only: it doesn't restrict scripts, so the Kit embed (`govcon-digest.kit.com`, `f.convertkit.com`, `app.kit.com`, `embed.filekitcdn.com`), reCAPTCHA and the Payload admin are unaffected — a full script CSP is future work and must be tested against all three. `nosniff` means scripts/styles must be served with correct content types (all are). Set these in the app only — don't add the same headers in Nginx/Apache, or responses carry duplicates.

**Rate limiting.** `lib/rateLimit.ts` throttles per client IP over a sliding window, in memory (fine because SQLite means one Node process — never run PM2 in cluster mode): `auth` 20 / 15 min (login, forgot/reset password, unlock — a `beforeOperation` hook, `payload/access/rateLimitAuth.ts`, so REST, GraphQL and the admin are all covered; Payload's per-account lockout still applies), `newsletter` 5 / 10 min (`subscribeNewsletterServer`), `contact` 5 / 10 min (`submitContactForm`). REST answers 429 (`/api/newsletter` adds `Retry-After`); server actions return a readable "Too many attempts" message instead. The client IP is `X-Real-IP`, else the rightmost `X-Forwarded-For` entry (Next.js fills that with the socket address when absent) — both forgeable by anyone who reaches the app directly, so **production must keep the app on 127.0.0.1 behind Nginx with `proxy_set_header X-Real-IP $remote_addr;`**. The newsletter forms carry a hidden `website` honeypot: if filled, the bot is told it subscribed and nothing is stored. The old `/api/contact` route was deleted — it skipped reCAPTCHA; the only live contact form (`/contact`) uses the `submitContactForm` server action. Verified by `scripts/test-rate-limit.ts`.

**Database.** SQLite by default (`@payloadcms/db-sqlite`) — see the `db` block in `payload.config.ts` and `DATABASE_URI` in `.env.example`; if `DATABASE_URI` is unset the adapter falls back to a local file (`data/payload.db`) so `npm run dev` works. To use Postgres/MySQL, install the matching `@payloadcms/db-*` adapter and swap the call. Migrations are committed in `migrations/` — run `npm run migrate` in every environment after pulling one. Dev push is disabled (`push: false`) — never re-enable it; a push-marked DB makes `payload migrate` refuse to run silently (symptom: `npm run migrate` prints nothing; fix: `DELETE FROM payload_migrations WHERE batch = -1`). `data/` and `/media/` are gitignored runtime state — **back them up in production**. Both locations are read when the app starts, never baked into the build: `DATABASE_URI` for the database and `MEDIA_DIR` for uploads (`mediaDir()` in `payload/collections/Media.ts`; unset = `./media` relative to the working directory). Never derive a runtime file path from `import.meta.url` — the build freezes it as the build machine's absolute path. In production set both to absolute paths outside the code checkout so deploys can't touch them.

**CMS 2FA (TOTP).** `proxy.ts` (Next 16's renamed middleware — exported function `proxy`, Node.js runtime) gates the admin root — no `payload-token` cookie → redirect to `/newsroom/sign-in`, which posts to `/api/users/login` with the code in an `x-authenticator-code` header; `payload/mfa/enforceMfa.ts` (a `beforeLogin` hook) verifies it against the user's hidden TOTP secret (`payload/mfa/totp.ts`, otplib v12 — pinned, v13 is an incompatible API rewrite). Enroll users with `npm run mfa -- <email>` (prints a terminal QR and confirms a six-digit code before enabling; existing enrollments are preserved); `--disable` is the lockout recovery. `/newsroom/login` always redirects to `/newsroom/sign-in`. Old `/dorbar` paths and `/cms-login` redirect to the new routes. MFA fields cannot be modified through public API writes; CLI enrollment uses explicit access override. First-time setup on an empty DB: the first admin is seeded automatically on boot from `CMS_ADMIN_EMAIL`/`CMS_ADMIN_PASSWORD` in `.env` (see `onInit` in `payload.config.ts`); changing those env values later does NOT update the existing user — use the admin panel for that.

**Data flow.** All public content comes from Payload — via `lib/cms.ts` on the server, or the REST API served by the `app/(payload)/api/[...slug]` catch-all (`/api/posts`, `/api/media`, `/api/users`). The only static route under `/api` is `/api/newsletter`, which wins over the catch-all for its own path. Never add a public `Cache-Control` header under `/api` in `next.config.mjs` — that would cache Payload's authenticated responses.

**Forms.** Server actions in `app/actions/`: `forms.ts` holds `subscribeNewsletterServer` (stores to the Payload `subscribers` collection; called by `/api/newsletter`), and `contact.ts` holds `submitContactForm` (validates with Zod and verifies reCAPTCHA, but only logs the message — wiring in email delivery is pending work).

**Next.js 16 specifics.** Builds use Turbopack, so `next.config.mjs` must not define a `webpack` function (`next build` fails if one is present; Payload's `withPayload` detects Next 16 and handles this itself). `next dev` writes to `.next/dev`, so a dev server and a production build can run side by side. Lint uses ESLint's flat config (`eslint.config.mjs`); the React Compiler rules that arrived with `eslint-config-next` 16 (`react-hooks/refs`, `set-state-in-effect`, `static-components`, `error-boundaries`) are set to warn because they flag existing template components. `images.minimumCacheTTL` is set explicitly (Next 16 changed the default to 4 hours), the image optimizer only accepts quality 75 unless `images.qualities` lists others, and local image URLs with query strings need `images.localPatterns`. `revalidateTag()` takes a second cacheLife argument (e.g. `'max'`). The frontend `<html>` carries `data-scroll-behavior="smooth"` so route changes jump to the top instantly despite Bootstrap's `scroll-behavior: smooth`.

**Styling and interactivity.** `app/globals.css` imports Bootstrap 5 CSS and the theme stylesheets from `public/assets/css/`. Bootstrap's JS bundle is **not** loaded — collapse/tab/dropdown behaviors are re-implemented with plain DOM listeners in `util/useBootstrap.ts`. Don't add `data-bs-*` components expecting Bootstrap JS to handle them; extend that file instead. Fonts are EB Garamond and Lora via `next/font`. Light/dark theming runs through `components/ui/ThemeProvider.tsx` (a `data-theme` attribute backed by `useSyncExternalStore`/`useInsertionEffect` hooks in `hooks/`).

**Images.** `lib/assets.ts` is a typed registry of all image assets (dimensions, alt text); typed wrappers (`ArticleImage`, `AuthorImage`, `UIImage`, `OptimizedImage`) live in `components/images/`. Prefer the registry over raw `<img>`/`<Image>` paths.

**SEO.** Each page exports `Metadata`; `lib/metadata.ts` generates JSON-LD structured data (rendered via `components/StructuredData.tsx`). Sitemap, robots, manifest, and RSS are code-generated from `SITE` config at `app/sitemap.ts`, `app/robots.ts`, `app/manifest.ts` (served as `/manifest.webmanifest`, auto-linked — do not add a manual `manifest` metadata field), and `app/feed.xml/route.ts`.

**`documentation/`** is the static HTML docs shipped with the purchased template — not part of the Next.js build; ignore it.

## Deployment

There is no CI/CD pipeline configured — deploy however the project requires. The app is a standard Next.js 16 + Payload server:

- Configure `.env` from `.env.example` for the target environment (`.env` is gitignored).
- Build and run: `npm ci && npm run migrate && npm run build && npm run start`.
- `npm run start` serves on port 3000 by default (`next start -p <port>` to change it); put a reverse proxy in front for TLS and the domain.
- `data/` (the database file, if using SQLite) and `media/` (uploads) are the CMS's entire state and are untracked by git — include them in the backup routine.
- If `npm run migrate` prints nothing, it did not run — see the Database section.
- `next.config.mjs` sets `generateBuildId` to a timestamp, so every build is a new ID — cache-busting is automatic, but builds are never reproducible.
- Long-lived caching headers for `/assets/*` are configured in `next.config.mjs`.
